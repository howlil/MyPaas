# MyPaaS v0.5.0-beta.1

**Release type:** Prerelease / beta  
**Release date:** 2026-08-16  
**Release tag:** `v0.5.0-beta.1`

This release is intended for self-hosted evaluation and small trusted-team workloads on a single Linux host.

## Included

- Git deployment through Dockerfile, Docker Compose, and static mode.
- Public OCI image deployment.
- Repository inspection, base-directory support, environment discovery, and Compose preflight checks.
- GitHub webhook deployments.
- Caddy-managed project routing.
- Deployment history, logs, metrics, restart, redeploy, and rollback for supported runtimes.
- Encrypted project environment values.
- Optional shared PostgreSQL provisioning.
- DB Studio Lite for PostgreSQL, MySQL, and MariaDB.
- Scheduled PostgreSQL backups and restore tooling.
- Managed image/build-cache retention.
- Optional `mypaas-statd` telemetry with engine-metrics fallback.
- Rootful Podman as the fresh-host default, with Docker Engine as an explicit compatibility mode.

## Reliability work before the beta

Controlled testing covered update/rollback behavior, backup/restore, concurrent deployment state, failed-deployment isolation, resource cleanup, Create Project behavior, and DB Studio connectivity.

That work found and fixed real defects, including Compose readiness/state divergence and Dockerfile replacement port self-collision.

These checks verify MyPaaS behavior. They are not a certification of how many applications, users, requests per second, or resource-intensive builds a particular VM can handle.

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/nabilrn/MyPaas/v0.5.0-beta.1/scripts/bootstrap.sh | \
  env MYPAAS_REF=v0.5.0-beta.1 bash
```

Fresh supported Ubuntu/Debian hosts default to rootful Podman. To intentionally use Docker Engine:

```bash
curl -fsSL https://raw.githubusercontent.com/nabilrn/MyPaas/v0.5.0-beta.1/scripts/bootstrap.sh | \
  env MYPAAS_REF=v0.5.0-beta.1 USE_PODMAN=false bash
```

Do not switch a stateful Docker installation to Podman in place. Use the supported migration/export path to a fresh host when changing engine families.

## Current limitations

- Single-host architecture; no multi-node HA or cluster scheduler.
- Owner / small trusted-team model; not a hostile multi-tenant security boundary.
- Public OCI registries only; private-registry credential storage is not implemented.
- No supported in-place Docker-to-Podman state migration.
- Build and runtime capacity depend on the application and the host resources available to it.

A static site, a small API, a large SSR build, and a database-heavy application can have very different CPU, memory, storage, and network requirements. This release therefore makes no universal project-count, user-count, or RPS claim.
